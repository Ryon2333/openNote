一、产品愿景与范围
1.1 用户核心场景
导入一份考研数学 PDF，连续阅读、双指缩放，使用触控笔在题目旁手写。
在第 18 题和第 19 题之间拖出 8 cm 留白，分界线以下原始 PDF 内容及关联笔迹随之下移。
留白内继续书写；支持调整、删除留白、撤销重做、保存与重新打开。
导出视觉准确、页序完整的 PDF；或将整个笔记库连同源 PDF、笔迹、留白和目录结构打包 ZIP，再恢复成可编辑状态。
在离线状态下运行；面对数百 MB 至数 GB 的 PDF 时采取按需渲染、受控缓存和安全降级，不因资源压力损坏笔记。

二、平台、架构与技术选型
首要设备：OPPO Pad 5，Android 16 / ColorOS 16；兼容 Android 13+ 平板。设备功能检测决定压感、倾斜、悬停、侧键等是否启用。
Kotlin + Android Studio + Gradle；Compose 用于外围 UI，手写核心采用自定义原生绘制层/合适的低延迟图形 API；禁止 WebView/HTML Canvas 充当主手写引擎。
评估 PDFium、MuPDF、Android PdfRenderer 等：核实随机读取、裁剪渲染、文本保留、加密 PDF、页面尺寸、内存、许可条款和维护情况。不能默认商业授权免费。
采用离线优先；无账户、广告、分析 SDK、在线授权或远程字体。正常使用不依赖 INTERNET 权限。
模块建议：app、core-model、core-storage、pdf-engine、ink-engine、layout-engine、export-engine、backup-engine、feature-library、feature-editor、feature-settings。实际按依赖关系适度调整。
采用分层架构，领域模型与 UI、PDF 引擎、数据库隔离；所有耗时任务在后台，严格控制主线程工作量。
三、手写引擎：以长期舒适书写为标准
3.1 输入采样与渲染
支持 ACTION_DOWN/MOVE/UP/CANCEL，消费 MotionEvent historical samples；以稳定时间顺序处理输入，避免漏点和重复点。
区分触控笔、手指、橡皮端、鼠标；支持仅触控笔书写、手指平移、双指缩放；掌触抑制应结合工具类型、接触面积和设备能力，不可简单禁用所有触摸。
在支持时读取压力、倾斜、方向、悬停和按钮；硬件不支持时合理退化，避免假装具备压感。
正在绘制的笔迹使用独立前景低延迟层，完成后合并到持久笔迹层；避免整页 Compose 重组和每采样点数据库写入。
笔迹平滑采用可配置滤波/曲线拟合；避免过度平滑导致数学符号变形；保留原始采样点或可逆参数以供重新渲染。
提供钢笔、圆珠笔、铅笔、荧光笔；压感曲线、笔宽、透明度、颜色收藏、快捷切笔、手写时的防误触和工具切换反馈。
支持矢量笔迹局部橡皮擦（切分路径）、整笔擦除、套索选中、平移/缩放/复制、撤销重做、形状识别（直线/圆/矩形/箭头）。
高缩放时笔迹边缘保持平滑，荧光笔混合与叠加规则稳定，透明笔迹导出视觉一致。
3.2 笔迹数据模型
Stroke 至少包括 UUID、文档 ID、锚点/页面 ID、点序列 (x,y,t,pressure,tilt)、画笔配置、层级、创建/修改时间、版本；点序列采用紧凑二进制编码、批量写入和必要的压缩。禁止将整页笔迹仅保存为不可编辑位图。
3.3 手写体验验收
用真实触控笔测试连续小字、积分号、矩阵、长横线、快速圈画；笔迹不得明显断裂、乱跳、变粗或位置漂移。
缩放/平移后笔迹与 PDF 坐标一致；连续书写 30 分钟，观察掉帧、内存增长、发热、保存可靠性。
记录输入到显示的延迟分布（如 p50/p95）及帧时间，不得把未测量的数字写成已达成指标。
四、页内动态留白：产品的核心差异化
4.1 精确定义
在原始 PDF 页面任意纵向分界位置插入指定高度的空白，使分界线以下原始 PDF 可视内容向下移动。不是插入整页、白色遮挡、OCR 重排，也不是仅移动笔迹。留白可被书写、调整、删除，并在导出时准确体现。
4.2 非破坏性布局模型
源 PDF 保持不可变；建立 SourceSegment(sourcePageId, yStart, yEnd)、BlankSegment(height, style)、InkObject(anchor, geometry) 等逻辑实体。
采用文档空间坐标、源 PDF 坐标、页面显示坐标、屏幕像素坐标、导出页面坐标五层映射，统一矩阵变换与逆变换；明确点、毫米、DPI 的转换。
布局改变只更新受影响的段位置与可见区缓存，不重新解析整个 PDF、不全量重绘。
留白支持触控拖动、精确输入高度、吸附/最小高度、横线/方格/点阵/纯白背景、合并相邻空白、撤销重做。
笔迹锚点分为源内容锚定、留白锚定、浮动对象；插入和删除留白时依规则移动；跨分界线笔迹需有明确行为与可撤销策略。
删除含笔迹的留白时必须询问如何处理笔迹（随区块删除、移动到邻近区域或取消），默认不能静默丢弃。
提供连续长画布与标准分页模式；分页应防止源内容丢失/重复、笔迹错位及不合理裁切。对于跨页数学公式，可优先保留完整片段或提供用户可控断页。
4.3 边界与反例测试
页首、页尾、极小留白、超长留白、多次嵌套留白、相邻留白合并、撤销后重做、不同页面尺寸混合。
旋转 PDF 页面、横向页面、CropBox/MediaBox 不一致、含图片或矢量图、扫描件、多栏排版。
留白中有笔迹、留白前后有笔迹、跨分界线的长笔迹、套索选择跨段内容。
保存后重新打开、ZIP 恢复后再次调整留白、PDF 导出后验证页面顺序与视觉位置。
五、PDF 阅读与 GB 级文件架构
5.1 基本阅读能力
多页连续纵向滚动、单页、横向翻页、适合宽度/整页、双指缩放、惯性滚动、页码跳转、缩略图、书签。
保留原始页面旋转与尺寸；尽量支持密码保护 PDF（通过用户本地输入密码），损坏 PDF 应提示错误并允许退出。
导入 URI 可能不支持 seek；引擎需要随机访问时，采用有进度、可取消、受空间约束的本地文件复制，不能把整个 PDF 读入 ByteArray。
5.2 渲染流水线
虚拟化页面：仅维护可见页面与少量邻近页；分级预览、标准清晰度、放大 Tile 局部高清渲染。
缓存采用明确的内存预算、LRU、可取消的预取、快速滚动降级；区分 CPU 内存、Bitmap、Native PDF 资源与 GPU 纹理。
渲染任务按可见性和交互优先级调度，页面快速切换时取消过时任务；资源释放与生命周期管理可追踪。
禁止一次性将数千页转位图、禁止将整个 PDF 载入 JVM Heap、禁止导出时将整本 PDF 拼为巨大内存对象。
对 10 MB、100 MB、500 MB、1 GB、2 GB、4 GB 的不同内容类型 PDF 建立分档测试。4 GB 是压力目标，不是无条件流畅保证；记录硬件、文件结构和失败原因。
出现内存压力时降级 Tile 分辨率、减少缓存并提示；单页渲染失败不得破坏笔记数据。
5.3 PDF 安全性与正确性
限制解析超时、并发和资源占用；对恶意 PDF、极端页面尺寸、加密/权限限制、损坏对象建立测试。
检查 PDF 引擎的许可、原生库 ABI、64 位支持和文件偏移限制；特别确认超过 2 GB / 4 GB 文件时是否存在 32 位偏移溢出。
支持导入进度、取消、失败清理、重复导入策略、空间不足提示和存储权限最小化。
六、笔记库与文件管理
创建空白笔记；A4/A5/自定义纸张；空白、横线、方格、点阵模板；支持多级文件夹、移动、复制、重命名、收藏、回收站、最近打开、排序和缩略图。
文档页可添加/删除/复制/重新排序；PDF 原始页与自建笔记页采用统一编辑模型。
搜索笔记标题与文件夹；OCR 和手写识别列为后续功能，不能阻碍首版架构。
自动恢复最近阅读位置、缩放状态（按合理策略）、当前工具与工具栏偏好。
提供明确的存储占用统计、缓存清理、原文件与笔记占用区分；清理缓存不得影响用户数据。
七、数据可靠性、持久化与迁移
源 PDF 与笔迹、布局、元数据分离；数据库采用 SQLite/Room 事务和适当 WAL；大二进制资源以文件存储并维护引用关系。
每条笔迹完成后异步提交；高频输入先进入缓冲；确保应用退后台时刷新待保存数据。
编辑操作采用统一 Command 模型（写入、擦除、移动、插入留白、删除留白、重排页面等），支持撤销重做；定义撤销栈的生命周期与重启策略。
关键操作应具备原子提交、崩溃恢复和一致性检查；禁止每次操作重写整个笔记库。
数据库 schema version、迁移脚本、兼容性测试从 v1 开始；升级不能通过清库解决。
删除操作采用回收站和延迟清理；重要批量操作显示确认、进度和失败反馈。
模拟杀进程、低电量、存储空间不足、备份中断、导出失败；验证数据不静默丢失。
八、PDF 导出：清晰、正确、可控
支持整本、指定页范围、当前页；导出包含原始内容、留白、笔迹、模板和正确页面顺序。
优先保留源 PDF 矢量对象及可选择文本；如因引擎限制栅格化，明确提示，并提供分辨率/文件大小选项，不得伪称矢量保留。
支持原尺寸、A4 标准分页和可选长页模式；明确跨页裁切与笔迹处理规则。
采用分批或流式写入，显示进度与取消，输出到临时文件后校验，再通过 Storage Access Framework 完成保存。
校验输出页数、文件可再次打开、留白和笔迹视觉位置；针对中文字体、数学公式、透明荧光笔、混合页面尺寸进行回归测试。
导出任务失败不覆盖已有正确文件，不破坏源笔记；清理临时文件。
九、ZIP / ZIP64 全库备份与恢复
9.1 备份内容与格式
ZIP 必须包含 manifest.json（版本、生成时间、文件清单、大小、哈希）、library.json（目录和笔记索引）、documents/（原 PDF）、annotations/（笔迹）、layouts/（留白布局）、settings/（可迁移设置）、checksums/（校验信息）。渲染缓存可不备份。采用稳定 UUID，不以文件名作为唯一 ID。
9.2 导出与导入规则
使用流式 ZIP64，支持超 4 GB 文件和大量条目；禁止内存中构建整个 ZIP；显示进度、可取消、空间预估、错误清理。
导入前检查备份版本、完整性、哈希、解压路径安全、条目数量、压缩比、总解压大小和可用空间，防止 ZIP Slip / ZIP Bomb。
支持整库替换、合并、保留重复笔记、按内容哈希跳过相同数据；替换操作必须二次确认并尽量支持回滚。
先在临时区验证和解析，再以事务方式提交；中途失败不能留下半套损坏笔记。
跨版本备份应有兼容矩阵；不支持的未来版本必须清晰提示，禁止静默导入并丢失字段。
备份-清空测试库-恢复-再次编辑-再次备份，核对源 PDF 哈希、笔迹数量与内容、留白布局、文件夹树、页面顺序、元数据。
十、交互与视觉体验细节
首页：最近笔记、文件夹、收藏、搜索、新建、导入、备份恢复；列表/网格切换，批量选择与移动。
编辑器：沉浸式阅读区域；可停靠/悬浮工具栏；常用画笔一键切换；撤销重做明显可见；留白工具作为一级操作。
工具栏不能遮挡笔尖附近区域；横竖屏自适应，支持左右手偏好、工具栏位置和手写区域留边。
缩放保持焦点附近位置；快速滚动和书写模式切换不能误落笔；页面加载显示占位缩略图而非整屏白闪。
手写光标、笔宽预览、橡皮擦范围、套索边界、留白拖动手柄要有清晰视觉反馈。
支持深浅色 UI；PDF 内容默认不反色，以免改变试卷颜色；夜间阅读可单独提供可关闭的页面调色策略。
可选工具音效/触觉反馈，但书写时不频繁震动；尊重系统字体缩放、屏幕方向、无障碍对比度与触控目标。
出现错误提供可理解的中文信息：文件损坏、密码错误、空间不足、备份不兼容、渲染失败、导出取消；不要显示裸异常堆栈。
不要模仿 Goodnotes 商标和专有资源；避免为了玻璃效果、动态背景牺牲帧率。
十一、隐私、安全与权限
完全离线可用；优先通过 Storage Access Framework 导入导出，最小权限原则，不要求访问整个文件系统。
不采集遥测、广告 ID、笔迹内容；不上传 PDF；无第三方统计 SDK；敏感内容不输出到日志。
应用私有目录中的笔记文件采用合理访问控制；系统备份策略明确，避免用户误以为 ZIP 备份已自动发生。
文件名、PDF 元数据、ZIP manifest 等不应暴露无关敏感信息；备份加密可作为后续可选功能，不能假装 ZIP 默认加密。
明确许可证义务、第三方声明、原生库安全更新流程；不要引入来源不明的二进制依赖。
十二、工程质量与自动化测试
12.1 自动化测试
单元测试：坐标变换及逆变换、布局分段、留白插入/删除、跨页分页、笔迹锚点、撤销重做、数据库迁移。
集成测试：导入→书写→留白→保存→重启→导出→重新打开；备份→恢复→继续编辑。
性质测试/模糊测试：随机插入/删除留白后保证片段有序、无重叠、无内容丢失、总高度一致。
压力测试：10 万级采样点、数万条笔迹、千页文档、反复缩放、滚动、杀进程、低存储、ZIP64。
基准测试：首屏时间、页面切换 p50/p95、帧时间、输入显示延迟、Java/Native/GPU 内存、导出吞吐、恢复耗时。
12.2 性能门槛
不得承诺所有设备和 PDF 都达到固定帧率。先建立可复现基准：普通试卷页面书写应稳定接近设备刷新能力；滚动不应持续阻塞主线程；100 MB 基准文件应可靠运行；随后逐级推进 500 MB、1 GB、2 GB、4 GB。每个结论必须注明设备、PDF 类型、测试步骤、实测数据和失败案例。
12.3 构建和 CI
Gradle Wrapper、版本目录、锁定依赖版本；至少有 Debug APK 构建与单元测试任务。
Lint、静态检查、许可证审计、可重复构建；不能提交密钥、私有凭据或开发者绝对路径。
README 写清 Windows 11 下 Android Studio 导入、JDK 版本、SDK 配置、连接 OPPO Pad 5、运行和生成 APK 的步骤。

十五、优先级明确的体验补充清单
左手/右手工具栏位置；快捷颜色与粗细预设；快速切换上一个工具；双击笔按钮切橡皮擦（设备支持时）。
书写时避免系统边缘手势误触；对 Android 手势导航区域进行合理处理。
PDF 页间切换时保留局部缩放状态策略；快速定位上次阅读位置；支持页面收藏。
套索选择时可跨越留白与 PDF 片段；复制到其他页面时转换坐标并保留画笔属性。
书写时误触“返回”或应用切后台，不丢笔迹；导入大文件过程中可以离开进度页但不造成任务孤儿。
恢复备份前展示笔记数量、文件大小、备份时间、兼容性与预估空间。
大文件打开失败时显示可操作的恢复建议，允许只读/低画质模式（引擎支持时）。
避免重复导入同一原始 PDF 占用大量存储；去重需基于内容哈希与引用计数，不能误删共享源文件。
长时间使用下避免无限增长的缩略图/渲染缓存，支持自动回收和用户手动清理。
