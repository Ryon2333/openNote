# v1 持久化与提交边界

SQLite schema user_version=1，外键开启，WAL开启。源文件和页面数据库分离。每次完成笔迹/擦除手势/布局操作后，在单个串行后台队列里事务提交当前页布局和已改变的笔迹记录。几何使用带版本的二进制编码，UUID不以文件名代替。未改变笔迹不重写binary payload。当前库没有每次操作全库重写。

页面读取按需加载笔迹；文档页尺寸先占位，打开当前页时测量并保存；导出时补测尚未打开页面。撤销快照仅针对受影响页面；会话最多30项/16MiB历史额度（极大单个快照可能被丢弃，S5需要delta command）。模型和数据库备份格式版本独立。

“已保存”只在事务成功返回后显示；队列中的未提交事件不保证在强杀时存在。SQLite会恢复先前完整提交，不能凭数据库事务声称所有未提交输入都不丢。切后台结束当前笔迹并排队保存，不阻塞主线程等IO。保存失败显式提示，可重试；源PDF不受影响。进程杀死、低存储等真实系统故障测试仍待阶段验收。

导入使用1MiB缓冲复制，不读整本到ByteArray；目标文件fsync，临时UUID目录验证PDF后rename并创建索引事务。导入未完成的源文件不计为用户已有笔记。磁盘文件和SQLite没有跨介质共同原子事务：崩溃可能留下无索引目录；后续一致性扫描/恢复需补齐，不能静默宣称已解决。

当前压感/倾斜/方向原始值保存，但画笔外观仍固定宽度；S3实现设备检测和压感曲线。只记录收到的采样值，不声称硬件支持了不存在的压感。
